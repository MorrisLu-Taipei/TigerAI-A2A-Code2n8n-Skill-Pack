# n8n.io 範本學習：方法與可重現性

> 🌐 [English](n8n-templates-method.en.md) | **繁體中文**

> 本檔記錄 `node-frequency.md` 與 `patterns.md` 的數字是怎麼來的、有哪些偏誤、以及為什麼 repo 只存統計。
> **本 repo 不收任何 n8n.io 範本 JSON、完整標題索引或作者資訊**；只收彙整統計、骨架模式，以及少量被引用的範本編號。

---

## 1. 立場：Skill 是大腦，範本是被消化的

- Skill 的角色是「大腦」：讀過大量公開範本之後，留下**描述性統計**與**歸納出的做法**。
- 範本不是被複製使用的素材。AI 產生 workflow 時，要用使用者環境目前可用的節點與參數重新建構；若參考了某個範本，只需告訴使用者參考了哪一個（編號與標題，網址指向 n8n.io 官方頁面）。
- 以 n8n 官方（n8n.io）公開範本為主要依據。早期放在 repo 的 2,061 支社群 workflow 參考語料（`reference-workflows/`）已於 2026-11-06 移除，不再作為依據。

## 2. 資料來源與取得方式

| 項目 | 內容 |
|---|---|
| 來源 | n8n 官方公開範本 API：`https://api.n8n.io/api/templates` |
| 索引端點 | `/search?rows=99&page=N`，逐頁取得範本清單（共 142 頁） |
| 明細端點 | `/workflows/<id>`，逐筆取得單一範本完整內容 |
| 抓取期間 | 2026-11-05 至 2026-11-06（約 13 個多小時） |
| 結果 | 索引回報 14,013 筆；去重後 13,947 個唯一 ID；13,947 筆全數取得，**失敗 0 筆**，解析失敗 0 筆 |

### 抓取方式：慢速、可續抓

- **慢速**：每次請求之間固定等待 2.5–3.5 秒（最短間隔加隨機抖動），整個流程循序進行、不平行。
- **自我表明**：請求的 User-Agent 標示為個人研究用途的慢速抓取，只使用公開 API，不帶任何帳號資訊。
- **遇錯退避**：HTTP 429 與 5xx 依序加長等待後重試（最多 6 次）；網路錯誤同樣退避重試；404 記錄為失敗，不硬抓。
- **可續抓**：已存在的檔案不會重抓；中斷後重跑只補缺的範本。寫檔採「先寫暫存再改名」，避免半截檔案。
- **本機保存**：原始資料只放在使用者本機，權限限本人讀寫，**不進 repo**。

## 3. 錨點（anchor manifest）與完整性

錨點的用途：讓之後重跑只補缺的範本，也讓「資料是否抓全」可以被比對，而不是憑印象。

- 錨點清單記錄：索引回報的總數、索引列出的唯一 ID 數、本機已有檔案數、每個檔案的 SHA-256 與大小、缺少的 ID 清單、多出的 ID 清單，以及 `complete` 旗標。
- 本次結果：索引唯一 ID 13,947、本機檔案 13,947、缺少 0、多出 0，`complete = true`。
- **索引回報總數（14,013）與實際列出的唯一 ID（13,947）差 66 筆**。逐頁取得的所有項目本身沒有重複，所以這 66 筆是 API 回報的總數與可列舉範本之間的差距；原因未查明（可能是已下架或未公開的範本，也可能是 API 計數方式），這裡不做推測。本統計一律以 13,947 為分母。
- 重跑時，錨點用來判斷哪些範本缺少；新上架的範本需要重新抓索引才會被發現，所以不同時間點抓到的結果會有差異。

## 4. 分析指標定義

所有比例的分母都是 13,947（全部範本），除非表格另有註明。**「N」一律是出現該節點的範本數，不是節點實例數**；唯一的例外是憑證類型，計的是節點綁定次數。

| 指標 | 定義 |
|---|---|
| 節點數 | 範本圖（`nodes`）中的節點個數，含 `stickyNote` |
| 規模分桶 | tiny ≤ 3、small 4–7、medium 8–15、large 16–30、xlarge 31+ 個節點 |
| 中位數／P90 | 對每個範本的節點數排序後取中位數與第 90 百分位（排序後從 0 起算的第 ⌊0.9 × 範本數⌋ 位） |
| 觸發器 | node type 以 `Trigger` 結尾，或為 `webhook`、舊版 `cron`；包含 `errorTrigger`、`executeWorkflowTrigger` |
| 觸發器組合 | 每個範本的「不重複觸發器集合」，每個範本只落在一種組合 |
| 節點共現 | 範本內兩種不同節點同時出現算 1 次；排除 `stickyNote`、`noOp`、`manualTrigger` 與所有觸發器 |
| 分類 | n8n.io 範本上的官方分類標籤，可多選 |
| AI 節點 | node type 以 `@n8n/n8n-nodes-langchain.` 開頭 |
| 語言模型廠商 | 依 `lm*` 節點分組；以含有任一語言模型節點的範本為分母 |
| 憑證類型 | 只取節點上綁定的憑證**類型名稱**，計「節點綁定次數」；不讀取、不保存任何憑證內容 |
| 有 sticky | 範本內至少有一個 `stickyNote` 節點 |
| 有錯誤處理 | 含 `errorTrigger`，或任一節點設了 `continueOnFail`，或任一節點有設定 `onError` 且值不是 `stopWorkflow`；**`retryOnFail` 另計，不併入** |
| 棄用節點 | `function`、`functionItem`、`cron`、`start`、`interval`；取代關係見 `node-frequency.md` §10 |
| 年份 | 範本在 n8n.io 的建立時間（`createdAt`）的年份，**不是範本內節點的版本** |

### 骨架分類（`patterns.md`）

- 共 14 個骨架，只看節點組成（例如「含 `webhook` 且含 `respondToWebhook`」），不判斷連線順序。
- 骨架**不互斥**，一個範本可以同時屬於多個骨架，所以占比加總會超過 100%。
- 代表範本：每類取「節點數 6–25 且有瀏覽數」的範本，依瀏覽數由高到低取前 3。

### 補算指標

棄用節點、`onError` 與重試設定、流程控制節點、觸發器組合，是在彙整統計之外，另以唯讀方式重新掃描全部範本補算的。補算結果與事前另行計算的數字逐項相符。

## 5. 可重現性

- **步驟**：抓索引 → 抓明細 → 建立錨點並確認完整 → 彙整統計 → 骨架分類 → 補算指標。
- **腳本與原始資料都留在使用者本機**，不收進本 repo；本 repo 只有結果。要重現，需要自行取得 API 資料並依上表的定義計算。
- **時點性**：範本會新增、修改或下架，不同時間重跑的數字會不同；本檔的數字固定為 2026-11-06 的版本。
- **數字來源**：本 repo 內文所有數字都來自上述彙整與補算，沒有憑印象填寫的數字。

## 6. 樣本偏誤與使用限制

- **偏新**：2025–2026 年建立的範本占 91.7%（12,789 / 13,947），2019–2024 年合計只有 1,158 個。舊年份的趨勢不可過度解讀。
- **偏 AI**：54.6% 的範本含 LangChain 系列節點；傳統整合情境的代表性較弱。
- **公開展示偏誤**：公開範本是寫給別人看的，所以 sticky note 比例（93.1%）遠高於一般內部 workflow 可能的比例。
- **流行度偏誤**：代表範本依瀏覽數挑選，反映受歡迎程度與曝光時間，不是設計品質。
- **只含官方公開範本**：不含企業內部或私有 workflow，也不含 n8n.io 以外的社群庫。
- **欄位限制**：分類標籤由作者與平台設定；`createdAt` 是範本建立時間；本統計沒有分析節點的 `typeVersion`，也沒有執行結果，所以無法判斷範本是否仍能在目前版本執行。
- **描述性統計，不是品質認證**：任何數字都不能解讀為「這樣做是對的」。

## 7. 授權與條款立場

- n8n.io 公開範本**沒有開源授權**。使用與再散布受 n8n 網站條款，以及範本作者分享時所適用的條款約束。
- 因此本專案採保守作法：
  1. repo **不存任何範本 JSON**，也不存範本說明文字。
  2. repo **不存作者姓名、簡介、頭像或個人連結**，也不存完整標題索引。
  3. repo 只存**彙整統計、歸納出的骨架模式，以及少量被引用的範本編號與標題**（`patterns.md` 引用 34 個，各附 n8n.io 官方頁面連結，供讀者自行查閱）。
  4. **不重新散布範本內容**；需要看原文時，請使用者同意後即時到 n8n.io 查閱。
- 這是本專案自訂的保守作法，不構成法律意見；若 n8n 的條款有變動，以官方公告為準。
